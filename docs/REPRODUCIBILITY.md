# Reproducibility guide: Quantum Claim Court

Everything below runs locally and free of charge. There are no IonQ or cloud calls and no API keys. Commands assume Linux or macOS with Python 3.13 or 3.14. On Windows, use `py -3.13` and `.venv\Scripts\python`.

## Know what you are looking at

| Kind of evidence | Where it comes from | What it can establish |
|---|---|---|
| **Literature-supported theorem** | Wootters & Zurek 1982; Bruß et al. 1998 (see `docs/submission/SCIENTIFIC_REFERENCES.md`) | No-cloning; the 5/6 optimum, within its stated assumptions |
| **Exact calculation for this circuit** | State vector (Qiskit, the stdlib verifiers, `scripts/exact_reference.py`) | F_A = F_B = 5/6 and F_AB = 2/3 for every input. Nothing about optimality. |
| **Live Qollab measurement** | One Run on Qollab's built-in simulator, or (R3b) IonQ's free noise-model simulator (2000 shots) | Built-in: consistency of this run with the exact values. IonQ: behaviour of the circuit under a simulated noise model, which may deviate from the ideal values. Not hardware, not a theorem. |
| **Local test fixture** | `dev/fixtures/*.txt`, generated by `dev/make_fixtures.py` from the real Python bridge with mock backends | Input for the browser tests only. Never a live result. |
| **Local counterfactual demonstration** | "Challenge the court" (84 cells), decided during the single Run by the frozen rules | LOCAL EVALUATION only. No new quantum job, no new research. |

## 1. Fresh environment

    python3 -m venv .venv
    .venv/bin/pip install -r requirements.txt          # qiskit==2.5.2 (pulls numpy, scipy)
    .venv/bin/pip install -r requirements-dev.txt      # pytest, playwright (browser tests only)

## 2. Build the Qollab application (byte-identical)

    .venv/bin/python scripts/build_r3b_zip.py          # -> dist/uqcc_r3b_ionq_compatible_rc.zip (pin: scripts/r3b_pins.json)
    .venv/bin/python scripts/build_r2_zip.py           # -> dist/uqcc_r2_claim_court_app.zip
    .venv/bin/python scripts/build_r1_zip.py           # -> dist/uqcc_r1_qollab_smoke.zip

The expected SHA-256 values are pinned in `scripts/frozen_pins.json`:
- R2: `8edd6166eb05d8b7acd00f9bab4a78d5a390bd5084415c9dd2996a129cf16ea0` (the ZIP the owner ran in Qollab)
- R1: `b20b03f766c0f837ec3941b5cb50dddd3bc7e9f121f1b0642090aa6e50e7f502`

The R2 build aborts if any frozen R1 science file differs from its pinned hash.

## 3–5. Run the circuit locally and get new raw counts

    .venv/bin/python scripts/local_run.py out/

- This runs exactly the bridge that Qollab calls (`uqcc_app.js_api.run_court`), on Qiskit's local `BasicSimulator`, unseeded.
- Each invocation produces new counts.
- It writes `out/evidence.txt` (the app's export text) and `out/console.txt`.

## 6–7. Recompute fidelities and 99% intervals yourself

- **Bit order:** key = `clone[1] clone[0]`. Clone A is the **rightmost** bit, clone B the leftmost.
- Fidelity counts:
  - F_A = (n00 + n10)/2000
  - F_B = (n00 + n01)/2000
  - F_AB = n00/2000
- Intervals: Wilson score intervals, family-wise 99% with Bonferroni over 3 observables, z = Φ⁻¹(1 − 0.01/6) = 2.935199.
- Example: the owner's real Qollab R2 run (00:1347, 01:327, 10:326) gives
  - A 1673/2000 → [0.810793, 0.859320]
  - B 1674/2000 → [0.811321, 0.859788]
  - AB 1347/2000 → [0.642035, 0.703476]
  - All three contain 5/6, 5/6 and 2/3.

## 8. Exact values from an independent implementation

    python3 -I scripts/exact_reference.py

This uses the standard library only and rebuilds the circuit from its documented angles. Expected output:
- P(00) = 2/3, P(01) = P(10) = 1/6, P(11) = 0 for the live input;
- 5/6, 5/6 and 2/3 on a 169-input grid.

## 9–11. Recompute every verdict, the 84 challenge cells, and the hash binding

    python3 -I qollab_r1/verifier/verify_uqcc_r1.py out/console.txt qollab_r1
    mkdir pkg && cd pkg && unzip ../dist/uqcc_r2_claim_court_app.zip && cd ..
    python3 -I pkg/verifier/verify_uqcc_r2.py out/evidence.txt pkg

For the R3b package, use `scripts/local_run.py out3b/ --r3b`, unzip `dist/uqcc_r3b_ionq_compatible_rc.zip`, and run `verifier/verify_uqcc_r3b.py`. It accepts BasicSimulator and IonQ-simulator evidence and re-checks the backend context. See `docs/R3B_IONQ_COMPATIBILITY.md`.

`verify_uqcc_r2.py` uses the standard library only and never imports Qiskit or app code. It:
- hashes the two evidence lines **exactly as printed**;
- checks that the court record is bound to the R1 evidence hash;
- recomputes counts, fidelities, intervals and the exact values (with its own state-vector simulator);
- re-decides the 14 R1 claims, the 4 value claims and all 84 challenge cells with its own rules;
- checks pre-registered verdicts.

Exit codes: 0 consistent, 2 valid but statistically inconsistent, 1 fail.

The same applies to evidence copied from a real Qollab Run: paste it into a file and run the same command.

## 12. Tests

    .venv/bin/python -m pytest -q                      # 185 tests incl. 37 headless-Chromium tests (R2 + R3b)
    node --test dev/js_tests/logic.test.mjs dev/js_tests/logic_r3b.test.mjs   # 27 JS tests (Node >= 20)

Optional, offline, with qiskit-ionq installed (no network; sockets are disabled):

    python scripts/ionq_offline_check.py <unzipped_r3b_package>

- The browser tests need a Chromium binary: `UQCC_CHROMIUM=/path/to/chrome`, defaulting to `/usr/bin/chromium`. Without one they are skipped.
- The browser tests use a **mock** bridge that replays fixtures from the real Python bridge. They do not prove behaviour inside real Qollab.

## Limits of inference

- One simulator run checks **one input state**. Universality of this circuit comes from the exact calculation, and **optimality comes from the literature**.
- 2000 shots give intervals about ±0.03 wide.
- About 1.4% of runs of this correct circuit show DISPUTED by chance (measured over 2000 local seeds).
- SHA-256 shows that a text is unchanged, not who produced it.
- The claim register is frozen and was structured by hand. This is not a general-purpose fact checker.
- Do **not** rerun `scripts/build_manifest.py` on the public snapshot. One raw record was redacted for copyright (see `evidence/README.md`), so the rebuilt R0 manifest would record a different hash. The committed manifests are authoritative.
